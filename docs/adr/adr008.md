ADR008 – Notifications email pour les événements critiques

Statut : Acceptée
Date : 2025-11-20
Fichier : /docs/adr/adr008.md

Contexte

Au-delà des notifications temps réel via WebSocket, les événements critiques de trading (exécution d'ordre, annulation, modification) nécessitent une trace persistante et accessible hors ligne. Les régulations financières exigent souvent un audit trail des communications avec les clients. De plus, les utilisateurs peuvent ne pas être connectés au moment de l'exécution de leurs ordres.

Décision

Intégrer JavaMailSender de Spring Boot pour l'envoi d'emails HTML formatés. Les notifications sont déclenchées lors des événements Saga (annulation, modification, exécution d'ordre) et envoyées de manière asynchrone pour ne pas bloquer les workflows principaux. Les emails contiennent les détails de la transaction (symbole, quantité, prix, timestamp) dans un format professionnel avec le branding BrokerX.

Conséquences

+ Trace persistante et auditable des opérations
+ Communication asynchrone indépendante de la connexion utilisateur
+ Conformité potentielle aux exigences réglementaires
+ Expérience utilisateur complète (temps réel + persistant)
- Dépendance à l'infrastructure SMTP
- Gestion des échecs d'envoi (retry, dead letter queue)
- Risque de spam si mal configuré

Alternatives considérées

SMS notifications - Plus coûteux et limité en contenu
Push notifications - Nécessite application mobile
Notifications dans l'application uniquement - Pas de trace persistante hors ligne
