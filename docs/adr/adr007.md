ADR007 – WebSocket pour les notifications temps réel

Statut : Acceptée
Date : 2025-11-20
Fichier : /docs/adr/adr007.md

Contexte

Les utilisateurs de la plateforme de trading doivent être informés en temps réel des changements d'état de leurs ordres (exécution, annulation, modification). Un simple polling HTTP serait inefficace et créerait une charge réseau inutile. Les utilisateurs s'attendent à une expérience réactive similaire aux plateformes de trading professionnel.

Décision

Implémenter WebSocket avec STOMP (Simple Text Oriented Messaging Protocol) via Spring WebSocket. Chaque client s'abonne à un topic personnalisé (/topic/orders/{clientEmail}) pour recevoir les notifications d'ordre en temps réel. Les services backend publishent les événements via SimpMessagingTemplate vers les clients connectés. L'authentification WebSocket utilise le même JWT que l'API REST.

Conséquences

+ Communication bidirectionnelle en temps réel
+ Réduction significative de la latence des notifications
+ Expérience utilisateur moderne et réactive
+ Compatible avec les architectures event-driven
- Gestion de la reconnexion automatique requise côté client
- Consommation de ressources serveur (connexions persistantes)
- Complexité ajoutée pour la scalabilité horizontale (sticky sessions ou message broker externe)

Alternatives considérées

Server-Sent Events (SSE) - Communication unidirectionnelle uniquement
Long Polling - Moins efficace, plus de complexité réseau
HTTP/2 Push - Support navigateur limité et moins flexible
